# 矩形板材下料 · 多订单拼版断头切割排料（Panel Nesting）

面向小型手作工坊的矩形板材裁切排样 Web 应用，支持**多张订单混合拼版**：
每张订单填写唯一订单号与零件清单（不同订单允许同名零件），系统按
**订单 → 零件行 → 数量的固定输入顺序**、遵循**断头切割（guillotine cut）**规则
逐板生成裁切方案，落位保留订单归属，并按订单输出跨板取件清单与材料费分摊。
发现损坏件时，可在分单取件清单中勾选后一键生成**独立补切方案**
（仅重排所选件，原方案落位与分摊不变）。

- 前端：React 18 + Vite
- 后端：Node.js + Express（排料 / 分摊 / 补切算法见 `server/src/cutting.js`）
- 部署：Docker / Docker Compose（镜像内完成依赖安装与前端构建，一键启动）

## 一条命令启动

```bash
docker compose up -d --build
```

该命令会自动完成：安装 npm 依赖 → 构建 React 静态资源 → 启动 Node 服务。

启动后访问：

> **http://localhost:8080**

停止服务：`docker compose down`

## 必要配置

| 配置项 | 说明 | 默认值 |
| --- | --- | --- |
| `PORT` | 宿主机暴露端口（在项目根目录 `.env` 中设置，可由 `.env.example` 复制） | `8080` |

容器内服务固定监听 8080 端口；如需改用 9090，可在 `.env` 中写 `PORT=9090`，
然后访问 http://localhost:9090 。

## 本地开发（不使用 Docker）

要求 Node.js ≥ 18。根目录一条命令安装所有 workspace 依赖：

```bash
npm install
```

分别启动后端（8080）与前端开发服务器（5173，已配置 `/api` 代理）：

```bash
npm run dev:server    # 终端 1
npm run dev:client    # 终端 2
```

访问 http://localhost:5173 。

生产方式本地运行（先构建再由 Express 托管）：

```bash
npm run build
npm start             # http://localhost:8080
```

算法自检（面积守恒、刀路几何、多订单归属、最大余数法分摊等）：

```bash
npm test
```

## 使用说明

1. 填写**原板长度、原板宽度、锯缝宽度**以及**每张原板材料价（元）**
   （非负、最多两位小数，可为 0；单位统一即可，长度通常用 mm）。
2. 可选填写**设备最大单刀长度**（单位与原板尺寸一致，通常为 mm）：
   - **留空 = 不限制**，完全沿用既有排料规则；
   - 填写时**必须为正数**；系统会在每个候选落位与朝向下分别计算
     **竖切优先、横切优先**两种切法的实际刀长，只从**所有刀长均不超过上限**
     的切法中按既有评分规则选取；现有板无可行落位时仍尝试新板，
     新板也无法加工时会明确报错（指出订单、零件与件号），**不会输出超限刀路**。
3. 在订单清单中为每张订单填写：
   - **唯一订单号**（留空则按“订单1、订单2…”自动编号，订单号不可重复）；
   - 零件行：名称、长度、宽度、数量；**同一订单内零件名不可重复**，
     **不同订单允许使用同名零件**（系统按“订单号 + 零件名”区分）。
   - 可添加 / 删除零件行与订单，或点击「载入示例」。
4. 点击「生成多订单裁切方案」。结果区显示：
   - **用板数**、零件总数、零件总面积、**锯缝损耗面积**、**余料总面积**、
     利用率、**材料费合计**，以及本次计算实际使用的**设备最大单刀长度**
     （未设置时显示“未设置（不限制单刀长度）”）；
   - **分单取件清单**：按订单列出每个零件件号、**所在板号**与**坐标 (x,y)**，
     跨板订单以高亮徽标提示所在板号，供分单取件；
   - **订单材料费汇总**：各订单零件数、面积、所在板号与材料费分摊额；
   - 每张板的裁切图（米黄色为余料、彩色块为零件且**左上角标注订单号**、
     灰色锯缝带上的虚线为刀刃，圆形数字徽章即**下刀次序**）、
     本板材料费分摊表，以及零件落位表（订单、坐标、尺寸、是否旋转）
     与刀路表（方向、起终点、贯穿长度）。
5. 若零件旋转后仍大于原板、订单号重复、板价非法，或设置了最大单刀长度后
   零件在现有板与新板上均无法在上限内加工，页面会明确报错（后者同时列出
   订单、零件与件号，且不会生成任何超限刀路）。
6. **缺件补切**：在「分单取件清单」的「补切」列勾选损坏件
   （按**订单号 + 零件名 + 件号**三元身份区分，跨订单同名零件互不影响），
   点击「生成补切方案」。系统以**当前排料输入**重新计算原方案并校验所选件
   存在且无重复，然后仅将所选件按**原始尺寸**与**原输入顺序**合并重排为
   独立补切方案——**原方案落位与材料费分摊保持不变**。结果区展示：
   - 补切件数、**新增板数**、**新增材料费**（新增板数 × 单板价）；
   - **补切清单**：逐件关联**原板号 → 新板号**，含坐标、尺寸与是否旋转；
   - 补切材料费按订单分摊表（规则同原方案）；
   - 每张补切新板的裁切板图（含**下刀次序**）与落位 / 刀路明细表。

## 切割规则

- 零件**严格按“订单输入顺序 → 订单内零件行顺序 → 数量 N 连续 N 件”**排料，
  不做大小重排；排料过程中不同订单的零件可共用同一张板（拼版）。
- 每件零件允许旋转 90°；余量相同时优先不旋转。
- 零件在所有已开板材中都放不下时才开启新板，尽量减少用板数。
- 每件零件落入某个当前可用矩形区域的左上角，需要两刀释放：
  - **竖切优先方案**：先竖切（贯穿该区域全高，刀长 = 区域高度），再在左侧料块上横切（刀长 = 零件长度）；
  - **横切优先方案**：先横切（贯穿该区域全宽，刀长 = 区域宽度），再在上侧料块上竖切（刀长 = 零件宽度）；
  - 自动选择锯缝损耗更小的方案，平局取竖切。
- **设备最大单刀长度（可选）**：留空不限制；填写正数上限后，系统在**每个候选落位与朝向**
  下分别验算上述两种切法的实际刀长，**只从所有刀长均不超过上限的切法中**按既有评分规则
  （锯缝损失小者优先、平局竖切，再按区域 / 坐标 / 已开板 / 不旋转）选取；
  现有板无可行落位（几何放不下或刀长超限）时**仍尝试新板**；
  新板的所有朝向与切法也都超限时，该订单 / 零件 / 件号会被明确指出并整体报错，
  **不输出任何超限刀路**（零件恰好占满某方向时该方向无刀，不参与长度判断）。
  上限对原方案与缺件补切方案同时生效。
- 每一刀都**贯穿当前所在矩形区域**，锯缝宽度从余料一侧扣除并计入损耗；
  沿板边的修整切若余边不足一条完整锯缝，则按实际余边宽度落刀。
- 零件在某方向恰好占满区域时，该方向不再下刀。
- 余料面积 = 原板总面积 − 零件面积 − 锯缝损耗面积。

## 缺件补切规则

- 损坏件以**订单号 + 零件名 + 件号**三元身份标识；不同订单的同名零件是不同件。
- 提交补切时，后端以**当前排料输入**重新计算原方案，并校验所选件
  **存在**（订单、零件名、件号均能对上）且**无重复**；任一不满足即整体报错。
- 仅所选件参与补切：按**原始尺寸**（未旋转的输入长 × 宽）与
  **原输入顺序**（订单 → 零件行 → 件号）合并，重排为**独立补切方案**；
  排料、旋转、锯缝与刀序规则与原方案一致；若设置了**设备最大单刀长度**，
  补切方案同样只采用所有刀长均不超过上限的切法，新板也无法加工时按
  订单 / 零件 / 件号报错。
- 原方案的落位、用板数与材料费分摊**不受补切影响**，原样返回。
- 补切新板按同样的单板价计费：新增材料费 = 新增板数 × 单板价，
  并在补切方案内按订单零件面积比例分摊（最大余数法）。
- 补切清单逐件给出：**原板号**（原方案所在板）与**新板号**（补切方案所在板）。

## 材料费分摊规则

- 每张开料板按固定的**单板材料价**计费；板价非负、最多两位小数，
  内部统一换算成整数“分”。
- 每张板内部，按**各订单在该板上的零件实际面积占比**分摊该板板价：
  先取各份额的整数分（向下取整），剩余尾差用
  **最大余数法（Hamilton / Largest Remainder）**逐分补入余数最大的订单；
  **余数相同时按订单输入顺序**优先。
- 因此保证：
  - 每板各订单分摊额之和 **严格等于该板板价**；
  - 各订单跨板汇总之和 **严格等于总板价（用板数 × 单板价）**。
- 板上没有任何零件落位的订单不参与该板分摊；板价为 0 时各订单分摊 0 元。

## API

`POST /api/cut`（多订单拼版）

```json
{
  "boardWidth": 2440,
  "boardHeight": 1220,
  "kerf": 3,
  "boardPrice": 180.00,
  "maxCutLength": 2400,
  "orders": [
    {
      "orderNo": "SO-1001",
      "parts": [
        { "name": "柜门", "width": 600, "height": 400, "quantity": 8 }
      ]
    },
    {
      "orderNo": "SO-1002",
      "parts": [
        { "name": "柜门", "width": 600, "height": 400, "quantity": 4 }
      ]
    }
  ]
}
```

参数说明：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `boardWidth` / `boardHeight` | 是 | 原板长度 / 宽度，必须为正数 |
| `kerf` | 否 | 锯缝宽度，非负，缺省为 0 |
| `boardPrice` | 否 | 每张原板材料价（元），非负、最多两位小数，缺省为 0 |
| `maxCutLength` | 否 | **设备最大单刀长度**，正数；省略 / `null` / `""` 均表示**不限制**（沿用既有排料规则）。设置后仅从竖切优先 / 横切优先中“所有刀长均不超过上限”的切法里选取 |
| `orders` | 是 | 订单清单（旧版顶层 `parts` 单订单写法仍兼容） |

返回（节选）：

```json
{
  "ok": true,
  "result": {
    "boardsCount": 3,
    "maxCutLength": 2400,
    "totalMaterialCents": 54000,
    "orders": [
      { "order": "SO-1001", "partsCount": 17, "partsArea": 2400000,
        "materialCents": 24411, "boardIndices": [1, 2] }
    ],
    "pickList": [
      { "order": "SO-1001", "items": [
        { "part": "柜门", "index": 1, "board": 1, "x": 0, "y": 0,
          "w": 600, "h": 400, "rotated": false }
      ] }
    ],
    "boards": [
      { "index": 2,
        "cost": { "priceCents": 18000, "shares": [
          { "order": "SO-1001", "area": 864000, "ratio": 35.62, "cents": 6411 },
          { "order": "SO-1002", "area": 1562000, "ratio": 64.38, "cents": 11589 }
        ] },
        "placements": [{ "order": "SO-1001", "part": "柜门", "index": 5, "...": "..." }],
        "cuts": [{ "seq": 1, "type": "v", "x1": 601.5, "...": "..." }]
      }
    ]
  }
}
```

- `orders[]`：按订单输入顺序的汇总，`materialCents` 为整数分，
  `boardIndices` 为该订单零件落位的板号（升序、去重）。
- `pickList[]`：分单取件清单，件内按板号升序、同板按切割（输入）顺序，
  含件号、板号与坐标。
- `boards[].cost.shares[]`：该板逐订单面积占比（`ratio` 百分比）与分摊额（分）。
- `maxCutLength`：本次计算实际使用的设备最大单刀长度；未设置时为 `null`。
  设置后返回的每一刀 `cuts[].length`（贯穿长度）都保证不超过该上限。

旧版单订单请求（顶层 `parts`、无 `orders` 与 `boardPrice`）仍然兼容，
整体视为单个自动编号订单、板价 0。

成功返回 `{ "ok": true, "result": { ... } }`；零件无法放入原板、输入非法，
或设置了 `maxCutLength` 后零件在现有板与新板上的所有落位 / 朝向 / 竖切 / 横切切法
均存在超过上限的刀长（错误信息含订单、零件、件号与上限值）时，返回
HTTP 400 与 `{ "ok": false, "error": "..." }`。

`POST /api/recut`（缺件补切）

请求体 = 排料输入（同 `/api/cut`）+ `damaged` 损坏件清单
（订单号 + 零件名 + 件号三元身份）：

```json
{
  "boardWidth": 2440,
  "boardHeight": 1220,
  "kerf": 3,
  "boardPrice": 180.00,
  "maxCutLength": 2400,
  "orders": [
    { "orderNo": "SO-1001", "parts": [{ "name": "柜门", "width": 600, "height": 400, "quantity": 8 }] },
    { "orderNo": "SO-1002", "parts": [{ "name": "柜门", "width": 600, "height": 400, "quantity": 4 }] }
  ],
  "damaged": [
    { "order": "SO-1001", "part": "柜门", "index": 1 },
    { "order": "SO-1001", "part": "柜门", "index": 3 },
    { "order": "SO-1002", "part": "柜门", "index": 2 }
  ]
}
```

返回（节选）：

```json
{
  "ok": true,
  "result": {
    "original": { "boardsCount": 2, "maxCutLength": 2400, "totalMaterialCents": 36000, "...": "同 /api/cut，原样不变" },
    "recut": {
      "maxCutLength": 2400,
      "damagedCount": 3,
      "addedBoards": 1,
      "addedMaterialCents": 18000,
      "items": [
        { "order": "SO-1001", "part": "柜门", "index": 1,
          "srcBoard": 1, "board": 1, "x": 0, "y": 0, "w": 600, "h": 400, "rotated": false },
        { "order": "SO-1001", "part": "柜门", "index": 3, "srcBoard": 1, "board": 1, "...": "..." },
        { "order": "SO-1002", "part": "柜门", "index": 2, "srcBoard": 2, "board": 1, "...": "..." }
      ],
      "orders": [
        { "order": "SO-1001", "partsCount": 2, "materialCents": 12000, "boardIndices": [1] }
      ],
      "boards": [
        { "index": 1,
          "placements": [{ "order": "SO-1001", "part": "柜门", "index": 1, "srcBoard": 1, "...": "..." }],
          "cuts": [{ "seq": 1, "type": "v", "...": "..." }],
          "cost": { "priceCents": 18000, "shares": ["..."] } }
      ]
    }
  }
}
```

- `original`：以当前输入重算的原方案，结构同 `/api/cut`，落位与分摊不受补切影响。
- `recut.items[]`：补切清单，`srcBoard` 为原板号、`board` 为新板号；
  按新板号升序、同板按原输入顺序（订单 → 零件行 → 件号）排列。
- `recut.addedBoards` / `recut.addedMaterialCents`：新增板数与新增材料费（分）。
- `recut.boards[]`：补切新板的落位（含 `srcBoard`）、刀序与逐板分摊，结构同原方案。
- `original.maxCutLength` / `recut.maxCutLength`：实际使用的最大单刀长度（未设置为 `null`）；
  补切刀路同样保证每刀 `length` 不超过上限，否则按订单 / 零件 / 件号返回 HTTP 400。
- 所选件不存在、重复选择或输入非法时返回 HTTP 400 与 `{ "ok": false, "error": "..." }`。
